먼저 답변을 말해 본 뒤 예시를 펼칩니다. 코드 예시는 연습용입니다. 경험을 설명할 때는 본인이 작성한 클래스나 메서드, 선택 이유, 실제로 확인한 결과를 넣습니다.

## 1. 프로세스·스레드

**면접 질문** · 프로세스와 스레드의 차이는 무엇인가요? 같은 서비스에 요청이 두 개 들어오면 무엇이 공유되나요?

**꼬리 질문** · 본인 서비스에서 요청별 상태는 어디에 두었나요? 요청마다 달라지는 값을 서비스 필드에 저장하면 어떤 일이 생기나요?

<details>
<summary>예시 답변 보기</summary>

프로세스는 독립적인 주소 공간을 갖는 실행 단위이고, 스레드는 프로세스 안에서 실행되는 흐름입니다. 같은 프로세스의 스레드는 힙 같은 메모리를 공유하면서 각자의 호출 스택을 가집니다. Spring 서비스 빈 하나를 여러 요청 스레드가 사용한다면 인스턴스 필드가 공유될 수 있습니다. 메서드의 지역 변수로 접근하더라도 그 참조가 가리키는 객체가 공유 객체인지 확인해야 합니다.

</details>

## 2. 가상 메모리

**면접 질문** · 페이지 폴트란 무엇인가요? 서버가 느릴 때 페이지 폴트가 늘었다는 것만으로 디스크가 원인이라고 볼 수 있나요?

**꼬리 질문** · 배포 후 첫 요청만 느리다면 가상 메모리 외에 어떤 초기화 작업도 비교해 보겠어요?

<details>
<summary>예시 답변 보기</summary>

프로세스가 접근한 가상 페이지에 대해 운영체제의 처리가 필요할 때 페이지 폴트가 발생합니다. 이미 메모리에 있는 페이지를 연결하는 경우도 있고, 디스크에서 데이터를 읽어야 하는 경우도 있습니다. 느려진 시간에 디스크 읽기를 수반하는 폴트가 늘었는지, 디스크 지연과 요청 시간도 함께 늘었는지 확인하겠습니다.

</details>

## 3. JVM 스택·힙·GC

**면접 질문** · 스택과 힙은 어떤 역할을 하나요? 힙이 계속 늘어날 때 무엇을 확인하겠어요?

**꼬리 질문** · 프로세스 메모리 사용량은 오르는데 JVM 힙은 평소와 비슷하다면 어떤 영역을 확인하겠어요?

<details>
<summary>예시 답변 보기</summary>

호출 스택에는 메서드 실행에 필요한 프레임이 쌓이고, 객체는 일반적으로 힙에 저장됩니다. GC는 루트에서 도달할 수 없는 객체를 회수할 수 있습니다. 먼저 GC가 끝난 뒤에도 살아 있는 객체의 양이 계속 늘어나는지 보겠습니다. 그런 패턴이 있다면 힙 덤프에서 메모리를 많이 점유한 객체와 어떤 참조가 그 객체를 붙잡고 있는지 확인하겠습니다.

</details>

## 1. 프로세스·스레드와 컨텍스트 스위칭

### 핵심 개념

프로그램은 실행할 명령을 작성한 결과물이고, 프로세스는 실행 중인 프로그램의 주소 공간과 자원 등을 포함한 실행 단위입니다. 같은 프로그램을 두 번 실행하면 서로 다른 프로세스가 될 수 있습니다.

스레드는 프로세스 안에서 실행되는 흐름입니다. 같은 프로세스의 스레드들은 주소 공간을 공유하고 각자 실행 위치와 레지스터 상태, 호출 스택 등을 가집니다. Java 서버를 실행한 프로세스 안에서도 요청 처리와 GC 등 여러 일을 위한 스레드가 동작할 수 있습니다.

| 구분 | 프로세스 | 같은 프로세스 안의 스레드 |
| --- | --- | --- |
| 메모리 | 일반적으로 별도 주소 공간 사용 | 같은 주소 공간 공유 |
| 데이터 전달 | IPC 등 전달 방식 필요 | 공유 객체 등을 통한 전달 가능 |
| 함께 고려할 문제 | 프로세스 간 통신과 자원 격리 | 공유 상태의 동시 변경 |

프로세스 사이에서도 명시적으로 공유 메모리를 구성할 수 있으므로 주소 공간의 분리와 공유 가능한 자원은 구분합니다.

### 동시성과 컨텍스트 스위칭

CPU가 실행 대상을 바꿀 때 이전 작업의 실행 상태를 저장하고 다음 작업의 상태를 복원하는 과정이 컨텍스트 스위칭입니다. 전환 자체의 작업과 캐시 상태 변화 등으로 비용이 생길 수 있습니다.

동시성은 여러 작업이 진행되는 구조이고, 병렬성은 여러 작업이 실제로 동시에 실행되는 경우를 말합니다. 하나의 CPU 코어에서도 작업을 번갈아 실행해 동시성을 만들 수 있습니다. 스레드 수를 늘렸다고 병렬 처리량이 같은 비율로 늘어나는 것은 아닙니다.

### 요청 처리 코드에 연결하기

여러 요청 스레드가 하나의 서비스 객체를 사용하면 서비스의 인스턴스 필드를 공유할 수 있습니다.

```java
class OrderService {
    private long lastMemberId;

    void remember(long memberId) {
        this.lastMemberId = memberId;
    }
}
```

위 객체를 여러 요청이 공유하면 다른 요청이 `lastMemberId`를 바꿀 수 있습니다. 요청별 값은 매개변수나 지역 변수로 전달하는 방법을 검토합니다. 지역 변수에 든 참조가 가리키는 객체 자체는 여러 스레드에 공유될 수 있으므로 객체의 공유 경로까지 확인합니다.

### 서버 지연과 연결되는 확인 순서

- CPU 계산이 많은지, DB·외부 API·락을 기다리는지 구간을 나눕니다.
- CPU 중심 작업에 실행 가능한 스레드가 지나치게 많으면 경쟁과 전환 비용을 살펴봅니다.
- I/O 대기가 많으면 스레드 수와 함께 외부 시스템의 처리 한도, 대기열, 타임아웃을 확인합니다.
- 평균 CPU만으로 원인을 정하지 않고 코어별 사용률과 스레드 상태를 함께 봅니다.

## 2. 가상 메모리와 페이지 폴트

### 핵심 개념

가상 메모리는 프로세스가 사용하는 주소 공간을 물리 메모리와 연결해 관리하는 방식입니다. 프로세스는 가상 주소를 사용하고, 하드웨어와 운영체제가 실제 물리 주소로의 변환과 접근 권한을 관리합니다.

페이징에서는 가상 주소 공간을 페이지 단위로 다룹니다. 페이지 테이블은 가상 페이지와 물리 메모리의 연결 및 관련 정보를 관리합니다. 프로세스가 가진 가상 주소 공간의 크기와 현재 RAM에 올라와 있는 양은 구분합니다.

### 페이지 폴트 처리

메모리 접근에서 페이지가 준비되지 않았거나 접근 권한 등의 처리가 필요하면 페이지 폴트가 발생할 수 있습니다. 운영체제는 유효한 접근인지 확인하고 필요한 처리를 수행합니다. 유효하지 않은 접근은 오류로 이어질 수 있습니다.

| Linux에서 보는 구분 | 의미 |
| --- | --- |
| Minor fault | 처리에 디스크 등 저장장치의 읽기가 필요하지 않은 폴트 |
| Major fault | 처리에 저장장치의 읽기가 필요한 폴트 |

요청한 데이터가 이미 메모리에 있거나 새 메모리 페이지를 준비하는 경우와, 저장장치에서 읽어야 하는 경우는 비용이 다를 수 있습니다. 폴트 횟수는 같은 시간 구간의 증가량과 요청량을 함께 봅니다.

### 처음 읽을 때 느린 경우

큰 파일을 처음 읽을 때와 반복해서 읽을 때 성능이 다르면 파일 캐시, 페이지 준비, 애플리케이션 초기화 등 여러 가설을 세울 수 있습니다. 일반 파일 읽기의 캐시 효과와 메모리 매핑의 페이지 폴트 경로도 구분해 설명합니다.

Major fault 증가, 저장장치 지연, swap 입출력, 프로세스의 실제 메모리 점유를 같은 시간대에 비교합니다. Minor fault만 증가한 상황을 곧바로 저장장치 병목으로 판단하지 않습니다. 첫 요청 지연에는 클래스 로딩과 JIT 컴파일, 연결 초기화 같은 JVM·애플리케이션 요인도 있을 수 있습니다.

- [Linux getrusage · Minor/Major page fault 정의](https://man7.org/linux/man-pages/man2/getrusage.2.html)

## 3. JVM 스택·힙과 GC

### 핵심 개념

JVM은 Java 바이트코드를 실행하는 가상 머신입니다. Java 서버 프로세스 안에서 JVM이 Java 실행에 필요한 메모리 영역을 관리합니다.

| 영역 | 설명 |
| --- | --- |
| JVM 스택 | 스레드마다 메서드 실행 프레임을 관리하며 지역 변수와 연산에 필요한 정보를 담음 |
| 힙 | 객체와 배열을 위한 메모리 영역으로 스레드들이 공유 |
| 메서드 영역 | 클래스 구조와 메서드 정보 등을 관리하는 논리적 영역 |

메서드 영역은 JVM 명세의 개념입니다. 실제 HotSpot의 메타데이터 영역인 Metaspace 등 구체 구현과 구분합니다. 실행 최적화가 가능하므로 개별 코드의 물리적 배치를 위 설명만으로 단정하지 않습니다.

### 참조 변수와 객체를 따라가기

```java
List<String> names = new ArrayList<>();
names.add("민지");
List<String> sameNames = names;
sameNames.add("지수");
```

`names`와 `sameNames`는 같은 목록 객체를 가리킵니다. 두 번째 변수에 대입했다고 목록 객체가 복사되지는 않습니다. 메서드의 지역 변수에 참조를 가지고 있다는 사실과 그 참조가 가리키는 객체를 여러 곳에서 사용하는지는 별도로 확인합니다.

### GC가 회수할 대상을 판단하는 관점

GC는 메모리를 자동 관리합니다. 기본적으로 실행 중인 스레드 등의 GC 루트에서 참조를 따라 도달할 수 있는 객체와 회수 가능한 객체를 구분해 이해할 수 있습니다. 객체들이 서로 참조해도 루트에서 도달할 경로가 없다면 회수 대상이 될 수 있습니다.

지역 변수 하나에 `null`을 대입해도 다른 참조가 남아 있다면 해당 객체에 도달할 수 있습니다. 회수 가능한 상태가 되는 시점과 실제로 GC가 회수하는 시점도 구분합니다.

### 오래 유지되는 컬렉션과 메모리 증가

```java
class RequestHistory {
    private final Map<Long, String> messages = new HashMap<>();

    void record(long requestId, String message) {
        messages.put(requestId, message);
    }
}
```

위 객체가 오래 살아 있고 서로 다른 요청 ID를 계속 추가하면 Map에 있는 메시지도 계속 참조될 수 있습니다. 업무상 보관 기간, 최대 건수, 삭제 정책을 검토해야 합니다. `final`은 Map 참조의 재할당을 제한하므로 내부 항목 수 증가를 막지는 않습니다.

### 지연이나 메모리 부족을 확인할 때

- GC 로그에서 수집 빈도, 정지 시간, 수집 전후 힙 사용량을 확인합니다. 수집기와 설정에 따라 동작은 달라집니다.
- 수집 후에도 유지되는 객체가 증가하면 힙 덤프에서 점유 객체와 참조 경로를 확인합니다. 덤프 수집 비용과 민감한 내용의 포함 가능성도 고려합니다.
- 프로세스 메모리가 늘지만 힙은 비슷하다면 스레드 스택, Metaspace, 직접 버퍼 등 힙 밖 영역을 함께 확인합니다.
- 깊은 재귀 호출로 스택이 부족한 경우와 객체 할당에 필요한 메모리가 부족한 경우를 구분합니다.
- GC로 인한 정지 시간과 API 지연을 같은 시간축에서 비교한 뒤 원인을 판단합니다.

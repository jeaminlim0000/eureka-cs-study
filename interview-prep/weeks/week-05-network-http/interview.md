## 1. HTTPS 요청 흐름

**면접 질문** · 브라우저에 HTTPS 주소를 입력하면 서버에 요청이 도착하기까지 어떤 일이 일어나나요?

**꼬리 질문** · 서버 로그에는 요청이 없는데 클라이언트에서 연결 타임아웃이 난다면 어디를 확인하겠어요?

<details>
<summary>예시 답변 보기</summary>

캐시나 기존 연결이 없는 일반적인 HTTPS 요청을 기준으로 설명하겠습니다. DNS로 호스트의 주소를 찾고, HTTP/1.1이나 HTTP/2라면 TCP 연결을 맺고 TLS에서 서버 인증서와 암호화에 필요한 정보를 확인합니다. 보안 연결이 준비되면 HTTP 요청을 보냅니다. 성능 문제라면 DNS, 연결, TLS, 첫 응답 바이트까지 걸린 시간을 구분해 보겠습니다.

</details>

## 2. HTTP와 멱등성

**면접 질문** · POST 요청이 타임아웃됐지만 서버에서는 저장이 끝났습니다. 재시도할 때 중복을 어떻게 막겠어요?

**꼬리 질문** · 키를 기록하고 실제 데이터를 저장하는 사이에 프로세스가 죽는다면 상태가 어긋나지 않게 어떻게 설계하겠어요?

<details>
<summary>예시 답변 보기</summary>

타임아웃만으로 저장 여부를 판단하기 어려우므로, 클라이언트가 첫 요청과 재시도에 같은 멱등 키를 보내도록 하겠습니다. 서버는 사용자나 작업 범위와 키 조합을 고유하게 관리하고, 처음 처리한 결과를 다시 반환할 수 있게 저장하겠습니다. 같은 키로 다른 입력이 들어오거나 동시에 같은 키가 들어오는 경우의 응답도 정하겠습니다.

</details>

## 3. 인증과 인가

**면접 질문** · 인증과 인가는 어떻게 다른가요? 본인 API에서 어디서 처리했나요?

**꼬리 질문** · 정상적으로 로그인한 사용자가 다른 사용자의 ID로 조회를 요청하면 어떤 테스트로 접근 차단을 확인하겠어요?

<details>
<summary>예시 답변 보기</summary>

인증은 요청자가 누구인지 확인하는 과정이고, 인가는 그 요청자가 특정 작업을 할 수 있는지 확인하는 과정입니다. 예를 들어 상담 내역 API라면 인증 단계에서 로그인 사용자를 식별하고, 실제 조회 시에는 해당 사용자가 그 상담을 볼 수 있는지도 확인합니다. 제 코드로는 사용자 ID를 얻는 지점과 조회 조건에 소유자 ID가 들어가는 부분을 보여드리겠습니다.

</details>

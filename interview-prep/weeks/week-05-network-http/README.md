1. DNS·TCP·TLS와 HTTPS 요청 흐름

세 주제 모두를 각자의 `notes/<GitHub-ID>.md` 한 파일에 정리합니다. 각자 주제별 Discussion 글을 하나씩 열고 글마다 기본 질문 1개와 응용 질문 1개를 올립니다.

## 출제 예시

1. **기본** · 브라우저에서 HTTPS 주소를 열면 서버에 요청이 도착하기까지 어떤 일이 일어나나요?
2. **내 코드** · 본인이 만든 API에서 HTTP 메서드와 상태 코드를 고른 이유, 입력 검증과 권한 확인 위치를 설명해 주세요.
3. **상황** · 클라이언트는 타임아웃을 받았지만 데이터는 이미 저장됐습니다. 같은 요청을 다시 보내도 중복 저장되지 않게 어떻게 설계하겠어요?

**공부할 때 확인할 점** · 클라이언트가 결과를 받지 못한 경우와 서버가 실제로 작업을 완료한 경우를 나눠서 재시도의 영향을 생각해 봅니다.

## 추가 질문은행

1. TCP와 UDP의 차이는 무엇인가요? TCP는 연결을 어떻게 맺고 손실을 어떻게 처리하나요?
2. HTTPS에서 암호화와 서버 인증은 각각 무엇을 해결하나요?
3. GET, POST, PUT, PATCH, DELETE는 언제 쓰나요? 안전성과 멱등성은 어떻게 다른가요?
4. 200, 201, 204, 400, 401, 403, 404, 409는 각각 어떤 응답에 적합한가요?
5. 쿠키, 세션, JWT는 각각 어떤 역할을 하나요? 클라이언트와 서버에는 어떤 값이 남나요?
6. 인증과 인가는 어떻게 다른가요? 리소스 소유자는 어디에서 확인하나요?
7. CORS와 CSRF는 어떻게 다른가요? 브라우저의 사전 요청은 어떤 경우에 발생하나요?
8. 연결 타임아웃과 읽기 타임아웃은 어떤 시점에 발생하나요?
9. API 테스트 도구에서는 성공하지만 브라우저에서는 실패합니다. 어떤 요청·응답 헤더부터 확인하겠어요?

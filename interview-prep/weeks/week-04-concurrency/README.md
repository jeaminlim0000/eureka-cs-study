## 세 명이 함께 공부할 주제

1. 경쟁 상태·원자성·가시성
2. 락과 데드락
3. 스레드 풀과 대기열

세 주제 모두를 각자의 `notes/<GitHub-ID>.md` 한 파일에 정리합니다. 각자 주제별 Discussion 글을 하나씩 열고 글마다 기본 질문 1개와 응용 질문 1개를 올립니다.

## 출제 예시

1. **기본** · 경쟁 상태는 언제 생기나요? 원자성과 가시성은 각각 어떤 문제를 설명하나요?
2. **내 코드** · 서비스 메서드에 요청 두 개가 들어오면 지역 변수, 서비스 필드, DB 데이터 중 무엇을 공유하나요?
3. **상황** · 동시 요청에서만 카운터 값이 틀립니다. 어떤 실행 순서에서 발생하는지 설명하고, 수정 후 어떻게 검증하겠어요?

**공부할 때 확인할 점** · 공유되는 데이터가 어디에 있는지 표시하고, 읽기·계산·쓰기 순서를 두 스레드로 나눠 그려 봅니다.

## 추가 질문은행

1. 동시성과 병렬성은 어떻게 다른가요? 작업 스레드 수와 실행 가능한 CPU 코어 수는 어떻게 연결되나요?
2. 두 스레드가 count++를 실행하면 어떤 순서에서 한 번의 증가가 사라지나요?
3. synchronized, volatile, AtomicInteger는 각각 어떤 문제를 해결하나요? volatile만으로 count++가 안전해지나요?
4. ConcurrentHashMap에서 containsKey()와 put()을 이어 호출하면 전체 연산도 원자적인가요?
5. 교착 상태의 네 가지 조건은 무엇인가요? 락 획득 순서를 통일하면 무엇이 달라지나요?
6. 스레드 풀을 사용하는 이유는 무엇인가요? 스레드와 대기열이 모두 차면 어떻게 되나요?
7. CPU 중심 작업과 I/O 대기가 많은 작업은 풀을 정할 때 무엇을 다르게 보나요?
8. ThreadLocal 값이 스레드 풀의 다음 요청까지 남는다면 어떤 문제가 생길 수 있나요?
9. 다른 사용자의 값이 가끔 응답에 섞입니다. 서비스 필드, ThreadLocal, 캐시 키 중 어디부터 보겠어요?

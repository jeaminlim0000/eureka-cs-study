## 세 명이 함께 공부할 주제

1. 응답 시간·p95/p99·오류율
2. DB 커넥션 풀과 외부 API 타임아웃
3. 로그와 트레이스로 지연 구간 찾기

세 주제 모두를 각자의 `notes/<GitHub-ID>.md` 한 파일에 정리합니다. 각자 주제별 Discussion 글을 하나씩 열고 글마다 기본 질문 1개와 응용 질문 1개를 올립니다.

## 출제 예시

1. **기본** · 평균 응답 시간과 p95·p99는 각각 무엇을 보여주나요? 요청량과 오류율을 왜 같은 시간대에 비교하나요?
2. **내 코드** · 만든 API 하나의 요청 경로를 그리고, 웹 서버 대기, DB, 외부 호출 중 어디가 느린지 현재 무엇으로 확인할 수 있는지 설명해 주세요.
3. **상황** · CPU와 메모리 사용률은 평소와 비슷한데 API가 느려졌습니다. 어떤 API와 인스턴스가 언제부터 느려졌는지 확인하고, 어떤 근거로 원인을 좁히겠어요?

**공부할 때 확인할 점** · 느려진 API와 시간대를 좁힌 뒤 요청 경로를 구간별로 나눕니다. 풀의 포화가 보이면 누가 자원을 오래 점유하는지 확인합니다.

## 면접관이 순서대로 줄 단서

1. 시작할 때 CPU·메모리가 정상이고 API가 느리다는 정보만 줍니다.
2. 영향 범위를 물으면 특정 목록 API의 p99만 올라갔다고 알려줍니다.
3. DB 구간을 나눠 물으면 SQL 실행 시간은 비슷하고 커넥션을 얻는 시간이 길어졌다고 답합니다.
4. 커넥션 풀 크기를 늘리기 전에 점유 시간, 대기 요청 수, 긴 트랜잭션 중 무엇을 확인할지 묻습니다.

## 추가 질문은행

1. 평균은 비슷한데 p99만 상승했습니다. 느린 요청을 어떤 기준으로 묶어 정상 요청과 비교하겠어요?
2. SQL 실행은 빠른데 DB 커넥션을 빌리는 데 오래 걸립니다. 풀 크기를 바꾸기 전에 무엇을 확인하겠어요?
3. Tomcat 스레드가 대부분 사용 중인데 CPU는 낮습니다. 스레드 덤프에서 어떤 대기 지점을 찾아보겠어요?
4. DB 구간이 느릴 때 커넥션 대기, 쿼리 실행, 락 대기를 어떻게 구분하나요?
5. 외부 API의 지연과 재시도가 함께 늘었습니다. 타임아웃, 재시도 횟수, 백오프를 각각 어떻게 검토하겠어요?
6. 배포 직후 일부 인스턴스에서만 오류가 늘었습니다. 요청, 버전, 인스턴스를 어떻게 비교하겠어요?
7. 캐시 도입 뒤 예전 값이 응답에 섞입니다. 캐시 키, TTL, 무효화 시점 중 무엇을 보겠어요?
8. 여러 요청에서 캐시가 동시에 만료됐습니다. 어떤 지표로 원본 DB 부하와 연결 짓겠어요?
9. 비동기 작업이 쌓입니다. 유입과 처리 속도, 반복 실패를 어떻게 구분하고 중복 메시지는 어떻게 다루겠어요?
10. 성능 수정 전후를 비교할 때 트래픽 조건과 어떤 지표를 맞춰야 하나요?

## 출제 예시

1. **기본** · 기본 프록시 방식에서 @Transactional은 어떻게 동작하나요? 같은 클래스 안에서 해당 메서드를 호출하면 어떻게 되나요?
2. **내 코드** · 직접 작성한 저장 코드의 호출 흐름과 트랜잭션 범위를 짚고, 실패 시 남는 데이터를 확인할 테스트를 설명해 주세요.
3. **상황** · 저장을 두 번 하는 기능에서 두 번째가 실패했는데 첫 번째 데이터가 남습니다. 호출 경로, 실제 트랜잭션 경계, 예외 처리 중 무엇을 확인하겠어요?

**공부할 때 확인할 점** · 트랜잭션을 기대한 메서드에 실제로 어떤 경로로 진입하는지, 예외가 어느 경계까지 전파되는지 함께 봅니다.

## 추가 질문은행

1. 요청이 들어와 JSON 응답이 나가기까지 Spring MVC에서 어떤 구성 요소를 거치나요?
2. 필터, 인터셉터, AOP는 각각 어느 지점에서 동작하나요?
3. @Valid 실패와 서비스의 도메인 예외는 어디서 응답으로 변환하나요?
4. 어떤 예외가 기본 롤백 대상인가요? 내부에서 잡거나 rollbackFor를 지정하면 무엇이 달라질 수 있나요?
5. REQUIRED와 REQUIRES_NEW는 기존 트랜잭션이 있을 때 각각 어떻게 동작하나요?
6. 영속성 컨텍스트, 1차 캐시, 변경 감지를 설명해 주세요.
7. flush와 commit은 어떻게 다른가요? SQL 실행 시점을 어떻게 확인하겠어요?
8. 목록 한 번과 각 항목의 연관 엔티티 조회가 반복되는 이유는 무엇인가요? SQL 로그에서 N+1을 어떻게 알아보나요?
9. Fetch join, EntityGraph, 배치 로딩은 어떻게 비교하나요? 컬렉션을 가져오면서 페이지네이션을 쓸 때 무엇을 확인하나요?
10. 엔티티와 API 응답 DTO를 분리하면 어떤 점을 제어할 수 있나요?
11. 단위 테스트와 통합 테스트는 각각 어떤 동작을 확인하나요? @WebMvcTest, @DataJpaTest, @SpringBootTest는 언제 쓰나요?

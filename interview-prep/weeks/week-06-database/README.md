[전체 목차](../../README.md) · [개념 노트 템플릿](../../templates/notes.md) · [Discussion 템플릿](../../templates/discussion.md) · [면접 질문과 예시 답변](interview.md)

## 세 명이 함께 공부할 주제

1. 조인과 제약 조건
2. 인덱스와 실행 계획
3. 트랜잭션·격리 수준·락

세 주제 모두를 각자의 `notes/<GitHub-ID>.md` 한 파일에 정리합니다. 각자 주제별 Discussion 글을 하나씩 열고 글마다 기본 질문 1개와 응용 질문 1개를 올립니다.

## 출제 예시

1. **기본** · 인덱스가 조회를 빠르게 하는 이유와 쓰기에 드는 비용을 설명해 주세요.
2. **내 코드** · 직접 작성한 쿼리 하나를 골라 조건과 정렬에 어떤 인덱스가 도움 될지, 실행 계획에서 무엇을 확인할지 설명해 주세요.
3. **상황** · 두 요청이 동시에 조회해서 둘 다 데이터가 없다고 판단한 뒤 같은 값을 저장했습니다. 무엇이 중복을 허용했고 어떻게 막겠어요?

**공부할 때 확인할 점** · 동시에 들어온 두 트랜잭션을 시간 순서로 그린 뒤 조회 시점과 DB가 제약을 검사하는 시점을 각각 표시합니다.

## 추가 질문은행

1. PK, FK, UNIQUE는 각각 무엇을 보장하나요?
2. INNER JOIN과 LEFT JOIN은 어떻게 다른가요? 오른쪽 테이블 조건을 ON과 WHERE 중 어디에 두는지에 따라 결과는 어떻게 달라지나요?
3. WHERE와 HAVING은 어떻게 다른가요? COUNT(*)와 COUNT(column)은 언제 결과가 달라지나요?
4. 복합 인덱스 컬럼 순서를 결정할 때 조건절과 정렬을 어떻게 함께 고려하나요?
5. 인덱스가 있어도 전체 테이블을 읽을 수 있는 이유는 무엇인가요?
6. 오프셋과 커서 페이지네이션은 어떻게 다른가요? 정렬 값이 같은 행은 어떻게 처리하나요?
7. ACID는 무엇인가요? 프로젝트에서 어떤 작업을 같은 트랜잭션으로 묶었나요?
8. Dirty Read, Non-repeatable Read, Phantom Read는 어떻게 다른가요?
9. 낙관적 락과 비관적 락은 충돌을 언제 확인하나요?
10. DB 데드락과 락 대기를 어떻게 구분하나요? 실패한 작업은 어떤 단위로 재시도하나요?
11. 목록 API가 데이터가 쌓인 뒤 느려졌습니다. 실행 계획에서 예상 행 수와 실제 행 수, 정렬, 인덱스 사용을 어떻게 살펴보겠어요?

## 1. 인터페이스와 다형성

**면접 질문** · 인터페이스 타입으로 메서드를 호출하면 어떤 구현이 실행되나요? 그걸 활용해 작성한 코드가 있나요?

**꼬리 질문** · 구현이 하나뿐이어도 그 인터페이스를 유지하겠어요? 당시 바뀔 가능성이 있던 부분은 무엇이었나요?

<details>
<summary>예시 답변 보기</summary>

인터페이스는 호출할 수 있는 동작을 정하고, 일반적인 인스턴스 메서드 호출에서는 실제 객체의 구현이 실행됩니다. 예를 들어 알림 서비스가 알림 발송 인터페이스에 의존하면, 이메일 구현을 전달한 환경에서는 이메일 발송 코드가 실행됩니다. 제 코드로 설명한다면 호출하는 서비스의 필드와 그 필드에 들어가는 구현체를 짚고, 왜 구현을 바꿀 필요가 있었는지 말씀드리겠습니다.

</details>

## 2. IoC와 생성자 주입

**면접 질문** · DI란 무엇인가요? 직접 작성한 서비스에서 생성자 주입을 사용한 지점을 설명해 주세요.

**꼬리 질문** · 테스트 대역을 넘겼다면 어떤 입력과 결과를 검증했나요? 실제 DB가 있어야 검증할 수 있는 부분은 무엇인가요?

<details>
<summary>예시 답변 보기</summary>

DI는 객체가 필요한 의존성을 외부에서 전달받는 방식입니다. 상담 조회 서비스라면 Repository를 `private final` 필드로 선언하고 생성자로 받습니다. `@RequiredArgsConstructor`는 생성자를 만들고, Spring은 서비스를 빈으로 만들 때 Repository 빈을 전달합니다. 이렇게 하면 필수 의존성이 생성자에 드러나고, 단위 테스트에서는 같은 생성자에 테스트 대역을 전달할 수 있습니다.

</details>

## 3. Spring 빈 등록과 주입 대상 선택

**면접 질문** · 같은 인터페이스를 구현한 빈을 추가한 뒤 애플리케이션이 시작하지 않습니다. 무엇을 확인하겠어요?

**꼬리 질문** · 어노테이션을 붙인 클래스가 빈으로 등록되지 않았다면 컴포넌트 스캔 범위와 설정 중 어디를 보겠어요?

<details>
<summary>예시 답변 보기</summary>

먼저 시작 오류를 보고 빈 자체가 없는지, 해당 타입의 후보가 여러 개인지 구분하겠습니다. 후보가 여러 개라면 생성자 매개변수 타입과 실제 빈 등록을 확인하겠습니다. 공통 기본 구현이 필요하면 `@Primary`를, 특정 서비스에서 특정 구현을 사용해야 하면 주입 지점에 `@Qualifier`를 지정하는 방식을 검토하겠습니다.

</details>

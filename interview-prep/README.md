## 매주 진행 방식

### 1. 세 주제를 모두 복습하고 정리합니다

기존 1~15주차 자료를 참고해, 각자 이번 주 공통 주제 3개를 Markdown 파일 하나에 정리합니다.

각 주제에는 다음 내용을 담습니다.

- 핵심 개념과 동작 원리
- 직접 작성한 코드 또는 개념을 보여주는 예시
- 개념을 확인한 공식 문서와 참고 자료

파일은 해당 주차 폴더의 `notes/<GitHub-ID>.md`에 올립니다. 면접 질문은 Discussion 본문에 작성하고, 답변·꼬리 질문·AI 참고 답변·복습은 그 글의 댓글로 이어갑니다.

예를 들어 면접 1주차는 기존 학습 13주차 Spring Core 내용을 연결해서 복습할 수 있습니다.

### 2. 각자 주제별로 질문을 출제합니다

각자 공통 주제마다 Discussion 글을 하나씩 올립니다. 글마다 **기본 질문 1개와 응용 질문 1개**를 준비합니다.

- **기본 질문**은 개념이나 동작 원리를 묻습니다.
- **응용 질문**은 직접 작성한 코드, 구현 선택 이유, 실무 상황에 연결합니다.

Discussion 제목은 아래처럼 맞춥니다.

`[면접 01주차][주제 2] IoC와 생성자 주입 · GitHub-ID`

한 사람당 질문 글 3개를 올리므로, 팀 전체로는 매주 Discussion 글 9개가 생깁니다.

### 3. 다른 두 명이 면접처럼 답합니다

각자 생각한 답을 먼저 작성하고 댓글로 올립니다. 출제자는 답변에서 더 확인하고 싶은 부분을 꼬리 질문으로 이어갑니다.

기본 개념은 **핵심 설명 → 동작 원리 → 짧은 예시** 순서로 답합니다.

코드 경험을 물으면 **구현한 기능 → 개념을 사용한 클래스나 메서드 → 선택 이유 → 확인한 결과** 순서로 답합니다.

상황형 질문은 **영향 범위 → 확인할 지표나 코드 → 결과에 따른 다음 확인** 순서로 답합니다.

### 4. AI 참고 답변과 비교하고 다시 답합니다

다른 두 명의 첫 답변과 꼬리 질문 답변이 올라오면 출제자가 AI 참고 답변을 공유합니다.

각자 다음 내용을 댓글로 남깁니다.

- 처음에 그렇게 생각한 이유
- 놓친 조건이나 다르게 해석한 부분
- 보완해서 다시 말할 답변

설명이 엇갈리면 공식 문서나 코드 실행으로 확인하고, 확인한 근거를 함께 남깁니다.

### 5. 같은 질문을 세 번 답해 봅니다

매주 각자 막혔던 질문 하나를 골라 복습합니다.

| 순서 | 시점 | 복습 방법 |
| --- | --- | --- |
| 1차 | 처음 질문을 받았을 때 | 자료를 확인하기 전에 본인 생각으로 답합니다. |
| 2차 | 다음 주 | 자료 없이 다시 설명하고, 빠뜨린 핵심을 확인합니다. |
| 3차 | 2~3주 뒤 | 조건을 바꾸거나 본인 프로젝트에 연결해 답합니다. |

복습 답변은 원래 Discussion에 댓글로 이어서 남깁니다. 8주차에는 앞 주차에서 반복해서 막혔던 질문도 함께 다룹니다.

## 질문과 답변 예시

**기본 질문**

생성자 주입이란 무엇이고, 필수 의존성을 생성자로 받는 이유는 무엇인가요?

**코드 연결 질문**

본인이 작성한 서비스에서 어떤 객체를 생성자로 받았나요? 그 객체는 어디에서 빈으로 등록되고 어떻게 주입되나요?

**첫 답변 예시**

“상담 내역 조회 서비스를 만들 때 Repository를 생성자로 받았습니다. 필수 의존성이 생성자에 드러나고, 서비스가 생성될 때 Spring이 등록된 Repository 빈을 전달합니다. 단위 테스트에서는 같은 생성자에 테스트 대역을 전달할 수 있습니다.”

**꼬리 질문**

실제로 작성한 테스트에서는 어떤 입력과 결과를 검증했나요? 실제 DB가 있어야 확인할 수 있는 동작은 무엇인가요?

경험을 설명할 때는 본인이 작성한 코드와 확인한 결과를 사용합니다. 직접 적용해 본 경험이 없다면, 적용할 수 있는 예시와 확인할 방법을 설명합니다.

## Process와 Thread

프로세스는 실행 중인 프로그램으로, OS에서 독립된 메모리와 자원을 할당받습니다. 스레드는 프로세스 안에서 실제 작업을 수행하는 실행 흐름입니다.

같은 프로세스의 스레드는 Code·Data·Heap 영역을 공유하고, 호출 흐름과 지역 변수는 각자 Stack에 보관합니다. 그래서 스레드는 통신 비용이 낮지만 공유 데이터 동기화 문제가 생길 수 있습니다.

## PCB와 Context Switching

PCB(Process Control Block)는 프로세스 상태, 프로그램 카운터, 레지스터 값, 메모리 정보 등을 보관합니다. Context Switching은 CPU가 실행 대상을 바꿀 때 현재 상태를 저장하고 다음 상태를 복원하는 과정입니다.

스레드가 너무 많아 Context Switching이 반복되면 실제 업무보다 상태 저장·복원에 CPU 시간이 쓰여 처리량이 감소할 수 있습니다.

## Java·백엔드 연결

서버 요청을 처리하는 스레드를 무작정 늘리면 메모리 사용량과 Context Switching이 증가합니다. I/O 대기가 많은 작업은 스레드 풀 크기, DB 커넥션 수, 외부 API 지연을 함께 고려해야 합니다.

스레드는 Heap과 Data 영역을 공유하므로 프로세스 간 통신 없이 데이터를 전달할 수 있고 생성·전환 비용이 작습니다. 반면 공유 데이터를 동시에 수정하면 Race Condition이 생길 수 있고, 한 스레드의 심각한 오류가 같은 프로세스 전체에 영향을 줄 수 있습니다.

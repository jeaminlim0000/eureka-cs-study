## 핵심 개념

TCP는 연결 지향적이고 신뢰성 있는 바이트 스트림 전송 프로토콜입니다. 패킷이 유실되거나 순서가 바뀌어도 순서 번호, ACK, 재전송을 이용해 수신 측에 순서대로 전달합니다.

## 연결과 전송

연결 시작에는 3-way Handshake를 사용합니다.

```text
클라이언트 SYN → 서버 SYN + ACK → 클라이언트 ACK
```

연결이 만들어진 뒤에는 데이터에 순서 번호를 붙이고, 수신자는 받은 범위를 ACK로 알립니다. 송신자가 제한 시간 안에 ACK를 받지 못하면 유실로 보고 재전송합니다.

## 흐름 제어와 혼잡 제어

- 흐름 제어는 수신 버퍼가 넘치지 않도록 수신자가 받을 수 있는 양을 알리는 방식입니다.
- 혼잡 제어는 네트워크 전체가 과부하되지 않도록 전송량을 조절하는 방식입니다.

둘 다 전송량을 조절하지만, 흐름 제어의 대상은 수신자이고 혼잡 제어의 대상은 네트워크입니다.

## Java·백엔드 연결

HTTP/1.1과 HTTP/2는 일반적으로 TCP 위에서 동작합니다. TCP 연결을 매 요청마다 새로 만들면 Handshake 비용이 반복되므로, HTTP Keep-Alive 또는 커넥션 풀로 연결을 재사용합니다.

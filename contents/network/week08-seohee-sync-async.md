## Sync와 Async의 차이

동기(Synchronous)는 호출한 쪽이 작업 결과를 받은 뒤 다음 흐름을 진행하는 방식입니다. 비동기(Asynchronous)는 요청을 보낸 뒤 결과를 나중에 콜백, Future, 메시지 등 별도 방식으로 받거나 처리합니다.

```text
동기: 주문 생성 → 결제 승인 결과 확인 → 주문 성공 응답
비동기: 주문 생성 → 알림 이벤트 발행 → 알림은 뒤에서 전송
```

결제 승인처럼 결과가 있어야 주문 성공 여부를 결정할 수 있는 작업은 동기 처리가 적합합니다. 카카오 알림처럼 실패해도 주문 자체를 취소하면 안 되는 작업은 비동기 후처리가 적합합니다.

## Blocking·Non-Blocking과의 관계

동기·비동기는 결과를 언제 받고 다음 흐름을 어떻게 이어 가는지에 관한 개념입니다. Blocking·Non-Blocking은 I/O를 기다리는 동안 호출 스레드가 멈추는지에 관한 개념입니다. 따라서 서로 같은 말이 아니며 조합될 수 있습니다.

## Java·Spring 예시

`CompletableFuture`는 비동기 작업의 완료 결과를 다룰 수 있고, 메시지 큐는 작업을 분리해 나중에 소비자가 처리하게 합니다. 다만 비동기 처리는 단순히 빠르게 만드는 방법이 아니라 실패 재시도, 중복 처리 방지, 순서 보장, 관측 가능성을 함께 설계해야 합니다.

## 알림 실패 대응

알림 이벤트를 바로 삭제하지 않고 처리 성공을 확인한 뒤 삭제해야 재시도가 가능합니다. 성공 응답이 유실되면 중복 전송될 수 있으므로 이벤트 ID를 기준으로 멱등성을 보장해야 합니다. 반복 실패한 메시지는 DLQ에 보관해 나중에 재처리합니다.

## 발표 중 확인한 질문

**알림을 비동기로 처리했는데 알림 서버가 장애가 나면 주문을 취소해야 하나요?**  
주문 성공과 알림은 분리해야 합니다. 알림 실패가 주문을 취소시키면 안 되고, 메시지를 보관한 뒤 재시도하거나 DLQ로 보내 복구해야 합니다. 이때 중복 전송 가능성을 고려해 이벤트 ID 기반 멱등 처리가 필요합니다.

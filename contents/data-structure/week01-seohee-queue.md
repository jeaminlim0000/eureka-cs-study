## 핵심 개념

Queue는 먼저 들어온 데이터가 먼저 나오는 FIFO(First In, First Out) 자료구조입니다. 삽입은 뒤(Rear)에서, 삭제는 앞(Front)에서 수행합니다.

| 연산 | 시간 복잡도 | 이유 |
| --- | --- | --- |
| 삽입 `offer` | O(1) | 뒤에 바로 추가합니다. |
| 삭제 `poll` | O(1) | 앞에서 바로 제거합니다. |
| 조회·탐색 | O(N) | 원하는 값을 앞부터 확인해야 합니다. |

## 배열 Queue의 문제와 해결

고정 크기 배열에서 앞쪽 데이터를 삭제하면 빈 공간이 생기지만, Rear가 배열 끝에 도달하면 더 넣지 못하는 가짜 포화 상태가 생길 수 있습니다. 모든 요소를 앞으로 당기면 O(N) 비용이 생기므로, Front와 Rear를 원형으로 연결하는 원형 큐로 해결합니다.

## Java 예시

```java
Queue<String> waiting = new ArrayDeque<>();
waiting.offer("주문-1");
waiting.offer("주문-2");

String firstOrder = waiting.poll(); // 주문-1
```

Java에서는 보통 `ArrayDeque`를 Queue 구현체로 사용합니다. 노드 객체를 따로 만들지 않고 연속된 배열 기반으로 동작해 일반적인 큐 작업에서 효율적입니다.

## 실무 연결

주문 대기열, 메시지 처리, 비동기 작업 대기열처럼 들어온 순서대로 처리해야 하는 상황에서 사용합니다. 긴급 작업을 먼저 처리해야 한다면 단순 Queue 대신 `PriorityQueue` 같은 별도 우선순위 정책을 선택해야 합니다.

## 발표 중 확인한 질문

**고정 크기 배열로 Queue를 구현할 때 어떤 문제가 발생하고, 해결책은 무엇인가요?**  
앞쪽 삭제 후 비어 있는 공간을 재사용하지 못해 Rear가 끝에 도달하면 가짜 포화 상태가 생깁니다. 전체 이동은 O(N)이므로, 인덱스를 순환시키는 원형 큐를 사용해 빈 공간을 재활용합니다.
